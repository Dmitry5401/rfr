# Домашнее задание к занятию 02. Окружение и агент

Результат сдаётся пулл-реквестом в ваш форк `rfr`.

## Часть 1. Стенд одной командой

1. Подтяните код занятия из бандла `rfr-l02.bundle` (лежит в материалах занятия) и создайте от него рабочую ветку:

   ```bash
   git fetch ./rfr-l02.bundle v3/l02-env-claude-live:v3/l02-env-claude
   git switch -c hw/02-env-agent v3/l02-env-claude
   ```

2. Если у вас остался контейнер `rfr-mysql`, запущенный через `docker run`, удалите его: `docker rm -f rfr-mysql`. Данные останутся в volume `mysql-volume`.
3. Поднимите стенд:

   ```bash
   docker compose up -d --wait                    # MySQL, ждём healthy
   ./gradlew runAll                               # rfr-auth и rfr-api параллельно
   (cd rfr-gql-client && npm ci && npm run dev)   # http://localhost:3001
   ./gradlew :rfr-e2e:installPlaywright           # браузер для тестов, один раз
   ./gradlew e2e --rerun-tasks
   ```

   Все тесты зелёные, `docker ps` показывает `rfr-mysql` со статусом `(healthy)`.

4. Сейчас `e2e` без `--rerun-tasks` пропускает прогон, если код не менялся. Сделайте так, чтобы задача запускала тесты всегда, и уберите `--rerun-tasks` из корневого `CLAUDE.md`. Подсказка: `outputs.upToDateWhen { false }` у задачи `:rfr-e2e:test`.

## Часть 2. Инструкции для агента

0. Адаптируйте документацию, настройки и хуки claude для своего агента
1. Откройте Claude Code в корне проекта и выполните `/memory`: убедитесь, что агент видит корневой `CLAUDE.md`, а `CLAUDE.md` модуля подгружается, когда агент читает файлы этого модуля.
2. Спросите агента, не подсказывая файлы: «Как поднять стенд и прогнать e2e?», «Что в `rfr-api` настоящее, а что мок?», «Почему успешный snackbar на фронте не доказывает сохранение?». Ответы должны опираться на `CLAUDE.md`; если агент ошибается, поправьте инструкции, а не ответ.
3. Документация отстала от кода: найдите в `README.md` (корневом и модулей) утверждения, которые больше не верны, и исправьте их. Например, `localenv.sh` больше не удаляет все Docker-контейнеры, а поднимает MySQL из `compose.yaml`, но README по-прежнему предупреждает об обратном. `CLAUDE.md` модулей отсылают к README за подробностями, поэтому устаревший текст сбивает и агента.
4. Каждая строка `CLAUDE.md` загружается в контекст. Удалите из модульных файлов то, что агент и так узнает из кода, и оставьте только неочевидное.

## Часть 3. Права и хуки

1. **Дыры в запретах.** Сейчас `.claude/settings.json` запрещает `git push *` и `rm *`. Найдите не меньше трёх способов обойти эти запреты (например, `git -C . push`, `find … -delete`, `unlink`, `git rm`), закройте их правилами `deny` и проверьте: агент получает отказ, а `mv файл .файл.<время>.bak` по-прежнему разрешён.
2. **Линтер в хуке.** Хук `.claude/hooks/compile.sh` компилирует фронт через `tsc`, но CI ещё гоняет ESLint. Добавьте в хук `eslint` для изменённого файла фронта. ESLint с flat config нужно запускать из `rfr-gql-client`, а путь к файлу передавать относительно этой папки.
3. **Проверка хука.** Сделайте заведомо некорректную правку в Java и в TSX и убедитесь, что агент получил ошибку компилятора и сам её исправил. Сохраните оба фрагмента вывода хука для PR.

## Часть 4. E2E в CI

Добавьте в `.github/workflows/ci.yml` job `e2e`, который поднимает стенд и прогоняет тесты на пулл-реквесте.

- MySQL — через `services` с образом `mysql:8.4.7`, портом 3306 и healthcheck, как в `compose.yaml`.
- Бэкенды — `./gradlew runAll` в фоне, фронт — `npm run dev` в фоне. Перед тестами дождитесь портов 9001, 8081 и 3001 с таймаутом, а не через `sleep`.
- Playwright на Ubuntu нужны системные библиотеки. Задача `installPlaywright` вызывает CLI Playwright с жёстко заданными аргументами `install chromium` и ставит только браузер. Добавьте в `rfr-e2e/build.gradle` свою задачу с аргументами `install --with-deps chromium` (или `install-deps chromium`) и вызывайте её в CI.
- Job запускается, только если менялись `rfr-auth`, `rfr-api`, `rfr-e2e`, `rfr-gql-client`, общие файлы Gradle или сам `ci.yml` — используйте outputs job `changes`.
- Результаты Allure (`rfr-e2e/build/allure-results`) загрузите артефактом и при падении тоже: `if: always()`.

Зелёный прогон job `e2e` в вашем PR — обязательная часть сдачи. Приложите ссылку на него и коротко опишите, сколько занимает job и что из этого времени съедает старт стенда.
